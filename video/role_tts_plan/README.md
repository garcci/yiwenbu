# 角色自然段套餐配音：准备完成，尚未运行

这是独立的 GitHub Actions 角色配音入口，不改变已生成的女主单段样音或视频工作流。当前仅有代码、结构示例和离线测试；没有提交、推送、触发CI或真实请求。后续优先在云端运行，本机只做必要准备和核对。

## 输入与复用

`manifest.example.json`只展示结构，`approval_state=draft`，即使误带`--execute`也会拒绝。正式台词尚待Gemini约束内小改及审定；不得将这里的两句示例当正式台词。定稿后新建清单，不覆盖原件，逐自然段填写：

- 唯一ID（例如`ep01_s01_xiaowen_p001`）、角色、完整自然段正文。
- 已确认可用的内置音色ID，不能填自动回退音色列表。
- 详细表演上下文：年龄、对象、情境、内在情绪及表达限制。上下文通过`context_texts`传入，与正文分开。
- 节奏方向及`speech_rate`，以自然语义组织停顿；不逐句拼接、不强拉统一语速，不从文本秒数推断实际时长。

角色示例只为字段示范：女声清澈梓梓；旧男声D为陶澄。内置音色的可用性和最终听感仍须以实际返回和用户试听为准，配置本身不证明可用或认可。

离线校验（不需要任何凭据、不创建音频）：

```sh
python3 -m unittest discover -s video/role_tts_plan/tests -v
python3 video/role_tts_plan/runner.py --manifest video/role_tts_plan/manifest.example.json
```

校验打印规范化清单SHA256、自然段数量与字符数。修改正文、音色、表演、节奏或审批状态都会改变摘要；费用证据必须绑定最终摘要。硬上限为每批20段、每段1000字符、全批8000字符，按Python Unicode字符计数，包含标点；这些是安全规模上限，不是费用结算单位，也不是建议一次把上限用满。

## 费用条件与启动方式

`.github/workflows/role_tts_plan.yml`已缩成固定唯一批次的一次性push入口：只匹配工作分支中`video/role_tts_plan/batches/batch01/execute_once.json`，目前真实触发文件不存在。没有workflow_dispatch、resume输入或schedule。代码、候选清单与trigger.example.json单独推送都不会生成；实际execute_once.json首次新增本身会触发一次运行，故只有当次实际额度与稿件均核定后才可准备真实触发文件并推送。

批次授权ID固定`ep01-role-tts-once-20261102-01`，费用证据同时绑定此ID与精确清单摘要。执行前使用Actions只读令牌查询专用workflow身份及远端运行历史，必须恰好仅有当前push run，run_attempt=1、SHA/仓库/工作流/事件均匹配。任何其他run、失败历史、缺失字段、历史不可读取或不明均停止，且在创建输出与发出TTS之前检查。全局批次concurrency不取消正在运行的任务。

这是审查要求的**保守单次push＋远端历史查询退路，不是持久原子消费服务**。它依赖GitHub保留并返回完整历史；管理员删除或改写历史、GitHub历史一致性异常不在其保证内。不能因此宣称永久防重放，也不能删除历史或改ID绕过门禁。该workflow首次出现run后即不再复用；失败或超时亦视为批次已消费/结果不明，新的请求必须先核明已有消费并采用新的独立受控批次。当前两批候选清单均已准备：batch01为20段640字符，batch02为7段198字符；第二独立工作流为`.github/workflows/role_tts_plan_batch02.yml`、授权ID尾号02、独立触发文件`batches/batch02/execute_once.json`。两工作流共享项目concurrency组，串行运行，各自只允许自己的首次push历史。正文已获本任务制片授权，不需要新增用户审批；候选音色仍待实际听审。

真正运行前必须只读核查当次Actions compute实际使用金额及包含金额、存储在免费额度内与零元预算阻止超额，以及Agent Plan套餐余量和TTS2超额后付费关闭。页面未显示剩余分钟时不推算或要求不存在的分钟字段。compute使用/包含金额必须为有限非负数，使用不得超过包含金额，包含余额至少USD 0.50；这些只是核查时快照，不承诺未来状态。不要因历史页面、成功记录或配置已保存推断当前状态。`quota_evidence.example.json`是拒绝执行的占位；实际证据记录来源、UTC时间、金额、开关、精确清单摘要、批准的本批请求数与字符数。一小时TTL采用各项独立核查中较早时间；任务超时10分钟。无法据AFP可靠换算字数时，不勾选`volc_character_budget_verified`，先核明实际字符范围是否在套餐内。

这份证据只是防误触的声明门槛，代码不会在线验证账单，也不能把手填true当费用事实。历史Medium余额及零元预算不自动覆盖将来的运行。没有确认时不创建正式触发清单、CLI也不得传`--execute`，不得修改预算、开后付费、扩令牌权限或切按量端点。

经主代理确认真实稿件与费用证据后，才能新增本唯一批次的正式清单并触发首次push。`ARK_API_KEY`仅由GitHub Secret注入，禁止命令行参数、JSON、日志或artifact保存密钥。只访问`https://openspeech.bytedance.com/api/v3/plan/tts/unidirectional`，资源固定`seed-tts-2.0`；不读取`ARK_PAYG_API_KEY`。每个自然段一个POST，逐段顺序执行；没有矩阵并发、自动换音色、自动重试、按量回退或模型下载安装。服务不支持所选音色时立即停止。

## 输出、停止和恢复

每段原始MP3保持服务原字节，配套receipt记录角色、音色、字符数、输入/音频摘要、时间、字节数、请求次数及未听审状态。冻结清单、费用证据与`state.json`保存在同一输出目录。artifact在失败或成功后均尝试保留1天，必须及时取回；runner硬终止时artifact上传并非绝对保证，不可把配置视为取回成功。

每次POST前先落`started`状态。任何服务错误、网络超时或中断都停止后续段落；超时结果可能已计入套餐，不能凭没收到音频直接重发。若上次state含失败/不明状态，恢复时拒绝自动重试；交由主代理检查实际结果与额度后决定新的受控请求。不得删除状态以绕过该保护。

原先的`resume_run_id`和可重复dispatch入口已撤下。脚本仍能验证本地已有完成音频的摘要，但这不构成跨run消费保证；真正生成始终必须通过唯一push历史门禁。不要新建空输出目录后复用旧费用证据来请求；第二个独立run会因远端历史已有记录而拒绝。


## 可选Drive项目目录

两条唯一push工作流现已接入云盘交付：先在无密钥步骤安装requests，随后只向生成进程注入既有三项Drive secrets，执行时带`--upload-drive`。任何TTS之前只读预检requests可导入、OAuth成功、固定父目录类型/写入能力/全部分页权限均可确认；失败则零TTS且不建目录。全部段落成功后复用预检的内存会话，重新核对父目录权限才创建唯一运行子目录并上传。复用现有`gdrive.py`的OAuth入口，**不复用**其同名覆盖与自动重试上传器。token只在内存；异常不打印原始响应、请求头、签名URL、令牌或异常内容。artifact始终尝试保留，即使后续云盘上传失败也保留已生成原音。

在创建任何子目录前，先读取固定父目录元数据与全部分页权限：必须为未删除的可写文件夹，权限非空且完整可读，只允许明确的user/group类型；anyone、domain、未知类型/角色、空权限、权限不可读、分页不明均停止且零创建。父目录通过后才在`11uMWY64q_tLolJ210NmLhfqnkW1D5fBR`内新建唯一运行子目录，并再次检查新目录元数据与全部权限；不通过则不上传任何媒体。只创建清单所属的原音及记录；逐文件读回核对父目录、大小与MD5。不会读取、覆盖或上传其他媒体，不修改分享/访问权限，不对外发布。若上传中断，保留本地artifact和已成功上传清单，不自动重试，也不删除已上传文件；新一次上传会建立新子目录，可能产生重复文件，应先检查原目录而非无界重跑。

代码不接受任何音频/参考文件字段，也不读取SeedAudio网页体验产物。`Result-10`、`Result-4`、`未命名`及软链接禁止作为输入或分段ID；上传只取本清单输出，不扫描散落素材。不要为本模块准备这些受禁来源，不搬运浏览器登录态。

## 权属与质量限制

Agent Plan API与网页体验中心是不同入口；本模块不依据体验页推断API或内置音色的商用许可。套餐专用端点已有代码和实际单段调用依据，但适用套餐及内置音色的准确公开/商业使用条款仍需单独核对。本模块只准备私人草稿，不宣称拥有公开发行或商用权；不模仿真人、不使用受禁真人/音频参考，不添加共享或发布步骤。官方端点资料入口：https://docs.volcengine.com/docs/ark/agent-plan-personal-voice-model?lang=zh 。此链接不能替代具体许可条款结论。

返回有效音频与完成码只证明传输结果，不证明台词发音、年龄、声线连续性、自然度、尾部提示音或表演质量。每段应实际试听并保留原件，再决定下一批。字幕须按实际音频对齐；解码、时间戳和数字范围检查不能代替用户听感或逐字同步验收。没有自动“质量通过”、剪尾、重编码、拼接或成片发布逻辑。
