# AI 配音的“活人感”：豆包 2.0 能力、社区实践与讲述稿改写

调研日期：2026-11-01  
拟用文件名：`voice_test/research_writing.md`

本次仅检索、阅读公开资料，没有修改文件、调用配音接口、下载他人音频或进行声音克隆。部分官方文档及社区页面只能读取搜索索引中的正文，直接打开存在超时或访问限制；相关缺口在下文标明。请求示例依据文档编写，未进行实际合成验证。

## 1. 豆包语音合成 2.0：哪些控制可以用

### 1.1 先确认模型和音色

火山引擎 HTTP 接口通过请求头 `X-Api-Resource-Id: seed-tts-2.0` 选择语音合成 2.0；`req_params.speaker` 必须匹配该版本音色。仅在正文中写“用豆包 2.0 配音”，不能证明调用了这个模型。`req_params.model` 涉及声音复刻的模型版本，不是普通预置音色切换到 2.0 的通用开关。[官方 HTTP 接口文档](https://docs.volcengine.com/docs/doubao-voice/unidirectional-streaming-text-to-speech-http?lang=zh)

官方音色表列有“少年梓辛 2.0”：

```text
zh_male_shaonianzixin_uranus_bigtts
```

它被标注支持指令遵循，可作为本次年轻男声的试音候选；**是否听起来像 19 岁、是否适合克制讲述，尚未试听核实**。音色名称不是效果保证。[官方音色列表](https://docs.volcengine.com/docs/doubao-voice/tone-list-3?lang=zh)

### 1.2 参数与适用边界

| 参数 | 文档支持的用途 | 本项目怎么用 |
|---|---|---|
| `req_params.additions.context_texts` | 自然语言语音指令，可描述语速、情绪、语气、音量等；V3 文档明确列表目前只有第一项有效 | 把“对谁说、怎么说、情绪变化”合并进一个字符串 |
| `req_params.audio_params.speech_rate` | 范围 `-50～100`，默认 `0`；端点分别对应 0.5 倍、2 倍速度 | 从 `0` 开始，必要时比较 `-5`、`-10`，以实际音频为准 |
| `req_params.audio_params.loudness_rate` | 范围 `-50～100`，默认 `0` | 起步保持 `0`，不要靠整体变响制造情绪 |
| `req_params.additions.post_process.pitch` | 整体音调调整，范围 `-12～12` | 起步不调；整体升降音调不能代替句内抑扬 |
| `req_params.additions.silence_duration` | 在本次输入文本末尾增加静音，范围 `0～30000ms` | 可用于分段间隔；不是给每个句号统一加停顿 |
| `req_params.additions.section_id` | 关联同一上下文中的串行合成请求 | 分段续讲时使用同一 ID；不同试验版本使用不同 ID |
| `req_params.audio_params.enable_subtitle` | 返回字级时间戳，支持中文、英文 | 用于初步检查；后期改变音频后，应重新对齐字幕 |

语音指令、串行上下文及末尾静音的依据见[官方双向流式 V3 文档](https://docs.volcengine.com/docs/doubao-voice/websocket-bidirectional-streaming-v3?lang=en)；语速、音量、音调及字幕参数见[官方单向流式 WebSocket 文档](https://docs.volcengine.com/docs/doubao-voice/unidirectional-streaming-text-to-speech-websocket?lang=zh)和[官方 HTTP 文档](https://docs.volcengine.com/docs/doubao-voice/unidirectional-streaming-text-to-speech-http?lang=zh)。

**重要格式：`additions` 是 JSON 序列化后的字符串，不是直接嵌套的 JSON 对象。** `context_texts` 应放在这个字符串内部，不能随意放到 `req_params` 顶层。

### 1.3 情感参数不能直接等同于 2.0 指令

V3 接口表列有：

- `audio_params.emotion`：指定情感类别，但只对支持该类别的部分音色有效。
- `audio_params.emotion_scale`：配合 `emotion` 使用，范围 `1～5`，默认 `4`，效果不是线性增长。

这不能推出每个 `seed-tts-2.0` 音色都支持 `emotion: "sad"`，也不能推出数值越大越自然。**“少年梓辛 2.0”对这套枚举参数的支持情况，本次未核实。** 本项目优先使用 `context_texts`，不在基线请求中叠加未经确认的情感枚举。[官方 V3 参数说明](https://docs.volcengine.com/docs/doubao-voice/http-chunked-sse-unidirectional-streaming-v3?lang=zh)

### 1.4 “语音指令”和“上下文”有什么区别

- **语音指令**回答“这段话怎么说”，例如：面对朋友、平静回忆、在某处迟疑。
- **上文语境**回答“为什么这样说”。官方声音复刻 2.0 最佳实践介绍过：将上一轮用户问题放入 `context_texts`，帮助回复匹配对话情绪。该示例来自复刻文档，不能无条件推广到所有预置音色与接口。[官方复刻最佳实践](https://docs.volcengine.com/docs/doubao-voice/sound-replication-20-best-practices?lang=zh)
- **`section_id`**用于关联已经合成过的串行请求，使后续请求读取历史；它不是无限长度的故事背景库。文档提到历史轮数和超时限制，具体数值本次未核实。[官方上下文说明](https://docs.volcengine.com/docs/doubao-voice/websocket-bidirectional-streaming-v3?lang=en)

本次短稿可以先整段合成。只有确实需要分段调整时，再引入 `section_id`；不必先把七句拆成七次请求。

### 1.5 SSML、停顿标签和语气词

**SSML 的官方说明存在冲突，不能给出“2.0 全部支持”或“全部不支持”的统一结论。**

| 官方页面 | 本次读到的说明 |
|---|---|
| [单向流式语音合成 HTTP](https://docs.volcengine.com/docs/doubao-voice/unidirectional-streaming-text-to-speech-http?lang=zh) | 列出 `ssml`，说明部分中英文音色支持，使用时需设置 `disable_markdown_filter=false` |
| [HTTP Chunked/SSE 单向流式 V3](https://docs.volcengine.com/docs/doubao-voice/http-chunked-sse-unidirectional-streaming-v3?lang=zh) | `req_params.ssml` 一栏仍写 TTS 2.0、ICL 2.0 音色暂不支持 |
| [SSML 标记语言](https://docs.volcengine.com/docs/doubao-voice/ssm-lmarkuplanguage?lang=en) | 明确排除部分 `_saturn_bigtts` 音色，并介绍 `<break>`；这不构成其他所有音色都支持的证明 |

通用 SSML 文档中，停顿写法为：

```xml
<speak>门没开<break time="400ms"/>东西也没递出去。</speak>
```

`<break/>` 默认停顿 1 秒；毫秒形式支持 `1～10000ms`。**这些是标签语法，不是本次音色已经实测支持的结论。** 要在具体接口、音色上核验标签是否生效，以及实际停顿是否符合预期。

其他容易混淆的标签：

| 写法 | 核实结果 |
|---|---|
| `<cot text=风格描述>内容</cot>` | V3 文档将其限制在声音复刻 2.0 的表现力增强版本，需启用 `use_tag_parser`；不能当成普通预置 TTS 2.0 音色的通用标签 |
| `{{"additions":{"context_texts":["语气自然一些"]} }}` | 官方实时音视频方案支持，但需要该方案开启标签解析；不能原样塞进普通 HTTP `text` 并假设有效 |
| `[#低声]`、`[停顿]`、`[叹气]` | 本次未核实为该 HTTP 接口通用官方语法 |
| 正文中的“嗯”“哎” | 是要读出的文字；本次未核实存在通用“自动添加自然语气词”参数 |

`<cot>` 的适用范围见[官方 V3 文档](https://docs.volcengine.com/docs/doubao-voice/websocket-bidirectional-streaming-v3?lang=en)；双大括号标签的解析条件见[官方实时音视频指令文档](https://docs.volcengine.com/docs/real-time-communication/control-voice-expression-with-instructions?lang=zh)。

本稿的“哎”是剧情事实，应保留；额外添加“嗯、啊、那个”不会自动增加活人感。

### 1.6 可以复制的基线请求

接口：

```text
POST https://openspeech.bytedance.com/api/v3/tts/unidirectional
```

请求头示意；实际使用时替换 API Key，并为每次请求生成新的 UUID：

```json
{
  "Content-Type": "application/json",
  "X-Api-Key": "<你的 API Key>",
  "X-Api-Resource-Id": "seed-tts-2.0",
  "X-Api-Request-Id": "<本次请求的 UUID>"
}
```

请求正文：

```json
{
  "req_params": {
    "text": "门没开，东西也没递出去。可那声“哎”，已经收不回来了。",
    "speaker": "zh_male_shaonianzixin_uranus_bigtts",
    "audio_params": {
      "format": "mp3",
      "sample_rate": 24000,
      "speech_rate": 0,
      "loudness_rate": 0,
      "enable_subtitle": true
    },
    "additions": "{\"context_texts\":[\"像一个年轻男人对面前的朋友讲自己的经历。语气自然，情绪克制，最后一句有一点后怕。不要播音腔、戏腔、笑声或夸张呼吸。\"],\"silence_duration\":300}"
  }
}
```

这是按[官方 HTTP 请求结构](https://docs.volcengine.com/docs/doubao-voice/unidirectional-streaming-text-to-speech-http?lang=zh)编写的请求体。返回的是流式响应，音频数据需要解析、解码并按顺序组装，不能把整个 HTTP 响应直接当作 MP3 文件。[官方流式响应说明](https://docs.volcengine.com/docs/doubao-voice/http-chunked-sse-unidirectional-streaming-v3?lang=zh)

以下仅用于核验 SSML 兼容性，**不是已验证可用的推荐版本**：

```json
{
  "req_params": {
    "text": "门没开，东西也没递出去。",
    "ssml": "<speak>门没开<break time=\"400ms\"/>东西也没递出去。</speak>",
    "speaker": "zh_male_shaonianzixin_uranus_bigtts",
    "audio_params": {
      "format": "mp3",
      "sample_rate": 24000
    },
    "additions": "{\"disable_markdown_filter\":false}"
  }
}
```

若出现标签被读出、停顿未改变或请求失败，回到纯文本基线；准确留白可在合成后编辑本项目音频。

**小红书、X 的证据缺口：** 本轮未获得能核对正文、作者及方法的相关原帖。小红书候选链接出现页面不可用，X 候选原帖也存在访问限制。因此不把聚合文章、转述和搜索标题写成平台共识。

据以上资料，可以整理出适用于本项目的做法；下面的具体取舍是本次建议：

- **书面改口语：** 优先使用主动句和具体动作；把过长句拆开，同时保留自然承接。短句不等于每四五个字就另起一句。
- **口头连接词：** “那会儿、到了、可、结果”等只在时间或逻辑关系需要时使用，不机械地给每句加“然后”。
- **自问自答：** 可以帮助交代复杂信息，但不是必需技巧。本次短稿不加“你猜是谁”等提问，避免破坏回忆口吻或增加叙述内容。
- **标点与留白：** 逗号表示句内承接，句号表示意思完成；不要指望它们对应固定停顿时长。少用连续感叹号和省略号。
- **整段还是逐句：** 先完整合成这段短稿，检查情绪连贯性；局部不合适时，按一个完整动作或情绪转折重做，不按字幕行机械切段。
- **后期处理：** 先修错读、重复、突兀停顿和拼接处音量，再加入音乐。不要一键删除全部静音，也不要用明显吸气、笑声或重混响掩盖平读。

### 3.3 本项目的音频检查表

下表是**待试听的起点**，不是行业标准、平台要求或任何博主的真实参数。

| 指标 | 统一测量方式 | 本项目起点 |
|---|---|---|
| 整体语速 | 实际说出的汉字数 ÷ 首字开始至末字结束的秒数 × 60；包含中间停顿，排除片头片尾静音 | 先比较约 200～260 字／分钟的听感；以清楚、自然为准 |
| 停顿 | 在无背景音乐的人声上，记录句内、句间和转折处的实际空白 | 普通承接可试 0.15～0.35 秒，意思结束可试 0.35～0.60 秒；关键处偶尔更长，不逐句套模板 |
| 音量／响度 | 记录整段 LUFS、真峰值和拼接前后的响度差 | 盲听版本统一播放响度；例如统一到约 −16 LUFS、真峰值不高于 −1 dBTP，保留内部强弱变化 |
| 情绪 | 让至少 3 人分别评分：聊天感、情绪清楚程度、刻意表演感，各 1～5 分 | 暂以聊天感及情绪清楚程度中位数 ≥4、刻意表演感 ≤2 为验收目标 |
| 忠实度 | 对照正文逐句听，确认词语与事实 | 不漏事实、不多出台词；特别检查“又”“没”“哎” |

FFmpeg 的 `silencedetect` 可以辅助找静音，`loudnorm` 可以报告或处理响度及真峰值；工具读数仍需结合试听，不能把低能量辅音误判为应删除的停顿。[FFmpeg 官方滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)

在没有可靠博主数值时，应先建立本项目自己的合格样音。后续版本与这条样音比较，不能宣称已经“接近某博主的客观参数”。

## 4. 可执行规则：共 9 条

1. **声音决定时间轴。**  
   旁白定稿 → TTS → 试听调整语速、停顿、音色 → 最终音频 → 转写出字幕时间轴 → 再排画面。任何音频剪切、变速或留白调整，都要更新字幕对齐；不按估算字数预先锁死镜头长度。

2. **旁白去 AI 味：删排比、删空话，一句只讲一个意思。**  
   删掉没有信息的感叹、总结和故作深沉的评价；书面被动句尽量改成自然主动句。保留故事本来需要的对照和反转，不为“去排比”删掉事实。

3. **把听众写进指令。**  
   明确是“19 岁年轻男人，对面前的朋友回忆经历”。年龄、关系和说话目的比泛泛的“富有感情、自然生动”更具体；声音仍须试听选定。

4. **起伏跟着事件走。**  
   开头交代死亡事实，听到声音处略有迟疑，结尾意识到回应收不回来。不要每句都紧张，也不要每个关键词都加重。

5. **标点先服务意思，再服务节奏。**  
   逗号连接，句号收束，问号只用于真正的问题。留白应给听众理解信息的时间；需要精确控制时，验证 SSML 或在后期编辑实际音频。

6. **先整段，后局部修。**  
   本稿先一次合成；需要重做时，保留相邻上下文，按完整语义段处理。分段串行合成可使用相同 `section_id`，独立试验版本不要混用历史。

7. **每轮只改变一个因素。**  
   分别比较原稿／口语稿、无指令／有指令、不同语速或音色。记录输入和结果，避免同时换稿、换音色、加音乐后无法判断改善来自哪里。

8. **后期保持声音清楚、连贯。**  
   修错读和接缝，平衡段间音量，保留有意义的停顿。清洁的 TTS 不必例行重降噪；先让干声通过试听，再决定是否加低干扰音乐。

9. **用量化指标检查最终音频。**  
   检查语速、停顿、响度和情绪评分是否接近已确认的项目对标。情绪不能只看音高或音量：数字合格但听起来像念稿，仍需返工。

## 5. 判断：更可能是模型问题，还是写法问题

**当前更值得优先验证的假设，是“写法和声音指导没有匹配目标”，但还不能排除模型或音色能力不足。**

理由有三点：

- 原稿已经很短，没有明显空话，问题不是单纯“句子太长”。“我抬起头。”独立成句、“火柴被我扣住了”的被动表达，以及连续短句，都有书面悬疑片段的节奏。如果再逐句合成，可能更像分镜说明。这是文本层面的推断。
- “换了七种声音”与“验证过七种讲述方式”不同。如果七版共享同一稿件、切段方式和无效指令，它们仍可能共享同一种念稿感。A 到 G 是否属于这种情况，未核实。
- 模型也有边界。开发者公开记录指出，豆包 2.0 对细微情绪提示和精确时长指令的响应可能较弱；说明写好提示不等于必然得到克制、细腻的讲述。[开发者实践记录](https://github.com/jianshuo/claude-skills/blob/main/wjs-voicedrop-reading-aloud/SKILL.md)

建议采用下面的对照，不再只轮换音色：

| 试验 | 文本 | 指令与处理 | 用途 |
|---|---|---|---|
| T1 | 原稿 | 同一音色、默认语速、整段、无风格指令 | 基线 |
| T2 | 口语稿 | 其余与 T1 相同 | 判断改稿是否改善 |
| T3 | 口语稿 | 加一个完整的 `context_texts` 指令 | 判断声音指导是否改善 |
| T4 | 口语稿 | 保持讲述目标，换另一款合适音色或模型 | 判断当前音色／模型是否构成主要限制 |

每个条件可以生成少量样本检查波动，统一响度后随机顺序盲听。T2 明显改善，支持写法问题；T3 才改善，支持指导方式问题；只有 T4 稳定改善，才更有理由把主要瓶颈归到原音色或模型。若 T4 同时换模型和音色，也只能判断整个方案改善，不能单独归因于模型。
